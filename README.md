# 拣货缺货拦截分析

> 一句话结论：用「账面库存 ≤ N 且/或 库存同步时滞 > M 小时」的低成本规则，在任务下发时拦截疑似缺货任务，预计可把缺货空跑损失从 X 分钟降到 Y 分钟（净节省 Z 分钟）。

## 根问题（我的判断）

表面现象是"拣货超时、订单取消上升"，但根因不是拣货流程本身，而是**库存数据失真**：

- 系统依据 `stock_synced_at` 时刻的账面库存（`book_stock`）下发拣货任务；
- 但账面快照与货架实际库存之间存在**时间差（时滞）**，商品实际已被拿走/售出，账面却仍显示"有货"；
- 于是拣货员拿着"有货"的指令去货架，实际无货 → 空跑、超时、取消。

**结论：问题是库存的"时效性/准确性"，不是拣货效率。** 对策是在任务下发环节做一次低成本拦截。

## 我做了什么

1. 数据探索：缺货率、`book_stock`/时滞/`aisle_traffic` 在缺货与成功任务间的差异。
2. 构造关键特征 `sync_lag_hours = created_at − stock_synced_at`（账面库存滞后时长）。
3. 设计并回测多条拦截规则（book_stock 阈值、时滞阈值、组合），用「净节省分钟」评估。

## 关键发现（数字均由 pick_tasks.csv 算出，脚本见 analysis.py）

- 缺货率：__%（有明确结果的任务中）
- 缺货任务的 `book_stock` 均值 __，成功任务 __ → 账面库存越低越易缺货
- 缺货任务的时滞均值 __ 小时，成功任务 __ 小时 → 账面越陈旧越易缺货
- 最优拦截规则：`book_stock ≤ __ 且 时滞 > __ 小时`
  - 召回率 __%（拦下真实缺货的比例）
  - 精确率 __%（拦截中真正缺货的比例）
  - 净节省 __ 分钟（对比不拦截基线损失 __ 分钟）

## 怎么证明有用

口径：到位缺货损失 90 分钟，提前拦截花费 10 分钟。
- 拦对一个（真缺货）＝ 省 90、花 10 → 净省 80 分钟
- 拦错一个（其实是成功）＝ 浪费 10 分钟
- **净收益 = 拦对 × 80 − 拦错 × 10**

用历史数据回测上述规则，得到净节省 Z 分钟；相比"不拦截"的基线损失，能挽回约 __% 的工时浪费。
